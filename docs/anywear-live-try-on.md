# 趋势试穿与跨站试穿浮窗

用户在趋势页发现款式，预览和下载单品图片，再通过配套扩展试穿；也可以到购物网站拖入商品图片试穿。扩展中点击“喜欢”后，原图、名称、类别及该次选图取得的来源链接保存在当前项目账号的“搭配记录 → 喜欢的穿搭”中。收藏可以刷新后查看、再次试穿或打开原商品页。

这是本项目的配套扩展，并不修改或调用原 Anywear Chrome 扩展。“我的衣橱”仍记录用户拥有的衣服；试穿收藏独立保存，不会自动成为已拥有的衣物。

## 项目内使用

1. 通过 HTTPS，或本机 `http://localhost` / `http://127.0.0.1` 打开项目并登录。
2. 在“穿搭趋势”的“趋势单品解析”中选择单品，点击“实时试穿”；已收藏单品可从“喜欢的穿搭”点击“再次试穿”。
3. 弹窗明确说明需要配套扩展。可切换预览单品、下载所选图片；点击“查看扩展安装引导”会打开趋势页的现有安装步骤。
4. 在桌面版 Chrome / Edge 安装并连接扩展，在扩展浮窗中选择刚下载的图片，确认名称和类别。阅读服务说明、同意开始后，在 Anywear 独立窗口允许摄像头。
5. 看到试穿画面后，在扩展窗口点击“喜欢，保存到项目”。在“搭配记录 → 喜欢的穿搭”查看。

列表只包含当前趋势提及、有可用图片且类别受支持的单品。现有趋势配图是本地款式示意图，预览标明“非原帖商品图”；它们不能代表原帖中的具体品牌或商品。下载为本地文件再上传扩展时，收藏按用户填写的信息保存，不自动继承原趋势的来源链接。支持上装、裤装、外套和连体装；鞋履、配饰及缺少图片的单品暂不能试穿。

项目内弹窗只提供图片预览、下载和扩展引导，不创建第三方 iframe、不申请摄像头、不自动发送图片，也不直接提交试穿收藏。页面切换和退出登录会关闭该弹窗。图片不可用时显示错误并隐藏下载入口，切换单品后可重试。

## 安装并使用跨站浮窗

在趋势页点击“开启跨站试穿”时，如果未检测到扩展连接，会自动打开五步安装引导：下载 ZIP、解压、在 Chrome / Edge 中加载扩展、连接项目、在购物网站使用。已经安装的用户可跳到连接步骤；扩展能响应但尚未绑定项目时，直接显示连接步骤。弹窗提供下载按钮、浏览器扩展页地址复制、上一步和关闭操作，连接成功后才显示准备完成。下载及解压由用户确认，网页不会将点击下载误判为安装完成。原有“下载配套扩展”和“首次使用怎么安装？”也可打开引导。

1. 从趋势页“下载配套扩展”，或使用 `frontend/public/downloads/zhiji-try-on-extension.zip`，解压到固定目录。
2. 打开 `chrome://extensions` 或 `edge://extensions`，开启“开发者模式”，选择“加载已解压的扩展程序”，选择包含 `manifest.json` 的解压目录。最低 Chromium 版本为 116。
3. 在项目网页打开浏览器工具栏的“知己跨站试穿”，点击“连接此项目网站”，批准该站点权限。回到趋势页点击“开启跨站试穿”，连接当前账号。
4. 保留已连接的项目标签页，打开购物网站。首次使用该网站时，再点击工具栏扩展的“在本站启用试穿浮窗”，授权当前购物网站。
5. 把网页中的衣服图片拖进浮窗，选择类别；第一次点击“同意并开始试穿”。如果图片来自独立的 CDN 域名，浏览器会单独询问是否允许读取那个图片站点。
6. 首次试穿时批准 Anywear 站点权限。0.1.2 将试穿画面、选图与收藏放在同一个独立窗口内；购物网页的初始浮窗会收起。在合一窗口中允许摄像头、观察效果并点击“喜欢，保存到项目”。点击“查看我的喜欢穿搭”可返回项目查看收藏。
7. 点击窗口顶部“置顶显示”，将画面和操作面板一起置顶。此后浏览其他网页时，可以把商品图片拖入该窗口的选图区域，或选择、拖入本地图片；读取新图片域名时仍需授权。

首次选图浮窗可以拖动、收起或关闭。合一窗口准备完成后会收起网页浮窗，购物页面导航、切换标签页或关闭源购物页都不会关闭合一窗口。试穿超时或服务结束时移除服务 frame，保留选图与收藏面板；更换单品只替换该窗口内的服务 frame，不再创建第二个窗口。直接关闭整个试穿窗口后，已授权购物网页恢复初始浮窗；停止跨站试穿、关闭已连接项目标签页或重新连接其他账号会清理对应窗口。浏览器重启后需重新在项目连接账号。

置顶使用 [Document Picture-in-Picture](https://developer.chrome.com/docs/web-platform/document-picture-in-picture)，由用户点击开启。置顶视图依赖原试穿窗口存活：关闭置顶视图会返回普通窗口，关闭原试穿窗口会同时关闭置顶视图。浏览器不支持该接口时保留普通合一窗口。切换置顶和普通模式会移动 iframe，浏览器可能重载控件并重新连接试穿服务，额度以服务方计算为准。跨窗口拖图若未携带商品页链接，收藏来源留空；不会根据图片 CDN 域名推测商品来源。

跨站场景支持 HTTPS 网站。普通局域网 HTTP 地址不在扩展授权范围中，也无法可靠使用摄像头。受保护的图片、防盗链、网站禁用图片拖动、非 JPG/PNG/WebP 格式等情况可能无法直接拖图读取；可以保存清晰的单品图，再使用浮窗的“选择图片”。先拖图再选择本地文件，可保留该次选择的商品来源链接；单独上传本地文件没有原商品链接。

## 图片、账号与收藏

- 扩展安装时不默认注入所有网页，也没有必需的全网站访问权限。可选权限范围用于用户逐站授权；脚本只注册到已经批准的具体站点。商品图片读取采用 `credentials: omit`，拒绝重定向，限制为不超过 10 MB 的 JPG、PNG、WebP。
- 项目登录 Cookie 由浏览器维护，不复制到扩展存储、购物网页或第三方试衣消息。收藏通过已连接项目标签页，在项目自身来源内使用现有 Cookie 和 CSRF 令牌提交。
- 保存前校验当前登录用户与连接账号一致；后端再次校验 `expectedUser` 与服务器认证身份。账号已变更时拒绝收藏，避免把单品保存到另一个账号。
- 后端通过 V12 迁移新增 `try_on_favorites` 表，使用现有私有 MinIO 图片存储。图片接口按当前账号查找并返回 `private, no-store`；不把对象存储密钥暴露给前端。同一账号对相同图片和来源重复收藏时返回已有记录。
- “喜欢穿搭”保存的是商品原图及来源，不保存摄像头录像或实时生成画面的截图。名称和类别可在跨站浮窗中修改后收藏。趋势示意款保留独立来源标记。
- 项目地址只能通过扩展自身的“连接此项目网站”按钮绑定或更换。购物网页的连接请求必须匹配这个地址，无法把收藏目标换到其他站点。
- 扩展会话存储保存连接账号标识、项目来源、所选商品的 URL/名称，以及试穿标识、所属购物标签页和独立窗口标识；图片字节存在浮窗内存，并在开始时通过隔离脚本传入试衣控件，不存入扩展存储。退出账号、停止跨站试穿或关闭连接标签页会清除扩展会话状态。长期存储只记住用户指定的项目来源，方便返回并限制连接地址。

API：

| 方法 | 地址 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/me/try-on-favorites` | 当前账号收藏 |
| POST | `/api/v1/me/try-on-favorites` | multipart 原图与元数据，需 CSRF |
| GET | `/api/v1/me/try-on-favorites/{id}/image` | 当前账号的私有收藏图片 |

## Anywear 服务边界

官方提供[网站控件安装方式](https://anywear.decart.ai/business)。本实现根据 2026-10-10 读取的官方控件，加载 `https://anywear.decart.ai/widget/latest/widget.html`，使用 `DECART_AUTO_START` 传入图片，使用 `DECART_TRACK_EVENT` 接收排队、首帧和会话状态。这些是托管控件的实际消息实现，服务方没有向本项目承诺独立版本稳定性；页面或协议更新后需重新核验。需要服务保障、生产域名接入或正式 SDK 时，应按[官方安装页](https://anywear.decart.ai/install)确认服务方案。

2026-10-14 及 2026-10-15 核验，该控件返回 `Content-Security-Policy: frame-ancestors 'self'`。实际 Chrome 复现确认：在购物网页或扩展页面嵌入时被浏览器拦截，iframe 的加载事件仍可能触发。因此 0.1.1 跨站扩展不再把第三方控件嵌在购物浮窗中，而是打开 Anywear 来源的独立窗口，在该来源内加载同源控件，符合服务方的嵌入策略。直接打开控件地址可能只显示控件说明页，独立窗口内的同源 frame 用于保留官方控件及消息协议。项目内旧的跨域试衣窗口已替换为明确的扩展使用说明、单品图片下载和安装引导，不再尝试加载被禁止嵌入的页面。正式网站内嵌接入仍需服务方提供允许嵌入的方案。

独立窗口需要用户首次批准 Anywear 的可选站点权限；扩展在隔离脚本环境中传入图片并转发当前试穿事件。0.1.2 把扩展操作面板作为与服务 frame 并列的 iframe，因此服务 frame 的祖先仍只有 Anywear 自己的来源。操作面板通过临时窗口标识连接扩展会话，图片只存在扩展面板及宿主隔离脚本的内存中，不放入地址栏或扩展存储。服务方来源、窗口标签页和试穿标识共同决定事件是否有效。原购物页只有在合一窗口接管前的加载阶段能够取消该窗口；接管后，其导航和关闭不再影响试穿。

项目内不加载第三方试穿页面；跨站扩展在用户同意后，才在独立服务窗口的同源 iframe 中运行试衣。控件委托摄像头和全屏，不委托麦克风。消息校验服务方来源、当前 iframe window，扩展转发额外校验独立窗口标签页，首帧须匹配当前试穿标识。项目的私有图片下载仍由项目自身登录会话授权，用户可随后在扩展中自行选择本地图片；不向试衣页面发送 Cookie、用户名、个人档案或 MinIO 凭证。

选中的商品图片和摄像头画面会交给 Anywear / Decart 处理。服务方有自己的额度、排队、账户、费用、缓存和数据保留策略，见[Decart 隐私政策](https://docs.platform.decart.ai/resources/privacy-policy)。移除 iframe 并不代表服务方已删除收到的内容；`norestore=1` 也不能保证禁止服务方内部恢复上一次图片。本项目只接受与当前标识匹配的首帧事件，但无法控制服务方自己的内部画面恢复行为。

试穿可参考款式和配色，不提供身体测量、尺码推荐或合身保证。本次实现不注册外部账号、不发布扩展商店、不部署项目；后端实际数据库会在正常应用启动时执行 V12。

## 构建和打包

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/package-try-on-extension.ps1
```

生成可直接加载的 `output/zhiji-try-on-extension`，以及前端可下载的 ZIP。不要直接加载源码目录 `browser-extension`：打包步骤会复制前端共用的试穿协议和图片工具。修改扩展或共用工具后，先重新打包，再在浏览器扩展管理页点击重新加载。

随后在 `frontend` 执行 `npm run build`。前端 Docker 构建仍以 `frontend` 为上下文，不依赖上下文外的 JavaScript 模块；打包好的 ZIP 会随静态资源复制到构建结果中。
