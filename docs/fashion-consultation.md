# 穿搭问答与衣橱搭配

知己助手默认进入“穿搭问答”。配色、风格、单品搭配和穿衣技巧直接走问答接口，无需先定位、获取天气或补齐衣物。例如“蓝色衬衫怎么配色？”、“白衬衫怎么搭出不同风格？”均属于咨询。

只有明确的衣橱生成请求（如“请用我的衣橱生成一套通勤搭配”）、选择“衣橱搭配”后发送需求，或点击搭配结果中的调整按钮，才进入原有推荐流程。涉及衣橱的配色或技巧咨询仍然直接回答。模糊输入优先留在问答；自然语言识别采用保守的有限规则，未识别的表达可通过模式按钮明确选择。手动选择“穿搭问答”后，该选择优先于文字自动判断，直到主动切换或点击生成快捷按钮。成功生成后回到默认问答模式，便于继续咨询。

## 问答接口

`POST /api/v1/assistant/consult` 需要登录和 CSRF token。

请求示例：

```json
{
  "question": "那鞋子呢？",
  "history": [
    { "role": "user", "text": "蓝色衬衫怎么配色？" },
    { "role": "assistant", "text": "可以用米白下装平衡蓝色。" }
  ]
}
```

问题、每条历史正文最长 2000 个 UTF-16 单元；历史最多 10 条，仅接受 `user` 和 `assistant`。前端只传最近的问答消息，不把错误提示或系统欢迎词作为上下文。对话保留在当前页面内存中，刷新或退出登录后清除，不新增数据库表。

成功响应的 `data` 包含：

- `answer`：可换行的纯文本讲解，以 Vue 文本插值展示。
- `examples`：当前账号真实衣物对象，最多 4 件；可以只引用一件衣物，不要求组成完整搭配。界面显示名称、颜色和已有图片，图片缺失或加载失败时使用明确的占位。
- `visuals`：最多 3 组通用搭配思路，每组最多 4 个“单品标签＋颜色名称＋六位十六进制色块”，以及解释文字。界面标明颜色为近似示意、组合不代表用户已拥有这些单品。问候等无需示意的回复允许为空数组。

后端只读取登录账号的衣橱，排除待人工确认的记录；按当前问题和近期问题的名称、类别、颜色相关性排序，最多向文本模型提供 80 件衣物的元数据。模型依据问题选择相关示例；无匹配时仍然回答，不强行使用无关单品。图片 URL、对象存储键和照片内容不发送给文本模型。

模型仅返回示例 ID，由后端解析回本次上下文中的真实衣物；未知或其他账号的 ID、重复 ID、超长内容、无效颜色和错误 JSON 均会拒绝。客户端提供的历史被包装为参考数据，不提升为系统指令。问答不会创建推荐记录、刷新搭配历史或触发生图。

## 模型与失败处理

独立问答复用管理员的 `OUTFIT_RECOMMENDATION` 文本模型配置、API key 与环境启用开关，无需新增配置项或数据库迁移。需要有效的文本模型配置；未启用或没有密钥时返回 503，提供方请求失败或结果无效时返回 502。界面说明失败并保留问题供重试，不把固定文案伪装成模型回答。登录失效时清除私人会话；旧账号的迟到结果不会展示在新会话。

原有 `/api/v1/recommendations` 的衣物归属、完整搭配、天气、保留与替换规则继续生效。

## 验证

后端 `ConsultationClientTest`、`ConsultationServiceTest`、`ConsultationControllerTest` 覆盖模型请求和格式、空衣橱、单件示例、较旧相关衣物、账号隔离、登录、CSRF、输入限制以及服务失败。前端 `useFashionApp-recommendations.test.mjs` 覆盖分流、独立接口、历史窗口和会话过期；`global-assistant.spec.js` 覆盖桌面、390×844 手机、色卡、衣橱照片、追问、错误重试与登录失效。

自动化测试使用模拟模型、模拟浏览器 API 和测试数据库，不证明线上配置或真实模型的回答质量。上线前需在实际文本模型启用的测试环境中做问答质量验收。
