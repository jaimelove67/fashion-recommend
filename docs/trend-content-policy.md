# 趋势内容范围与图片复核

本规则用于日常服装搭配参考。正常半身穿搭、上装展示、鞋包配饰和单品细节可以收录；不要求每张图都是全身照。不能仅根据领型、裸露手臂、性别或体型判定不合格。

排除以胸、臀等身体局部为主要焦点、缺少服装展示信息的特写，以及明显的性暗示、挑逗、色情宣传内容。服装与配饰应是画面和文字的主要信息。仍沿用视频、纯文字、红毯、秀场、明星宣传和超时内容等原有排除规则。

## 采集与公开展示

1. 新旧采集入口都先检查完整文案。明确的身体特写、擦边、性暗示等词语被拒绝；“衬衫胸前口袋”“大胸女生尺码建议”“吊带配开衫”等正常服装用语保留。
2. OOTD、穿搭标签及“有图片”只能说明候选相关，不能代替检查图片。采集成功的内容以 `PENDING_HUMAN` 待复核状态保存，不会立即公开。
3. 复核必须检查封面和所有拟发布图片。混合图集中的未复核图片应留在候选中，不能随已通过封面一起放行。拒绝内容保留原因并隐藏，重新采集不会将其恢复。
4. 公开列表和搭配参考接口只读取未隐藏、已明确通过、且内容版本仍匹配的记录。更换封面、图集、正文摘要、作者、标签或原帖链接后，原通过状态失效，需再次复核。单纯更新互动数和采集时间不会导致重复复核。

当前实现是文字初筛加明确的图片复核门槛，没有新增自动图片分类模型，也不会把关键词检查冒充成图片识别结果。图集的审核结论只适用于实际检查过的内容版本。图像在相同 URL 下被远端替换的情况仍需重新检查；版本绑定按图片 URL 和所存文字工作，不对远端图片字节作持续监测。

## 管理员复核接口

管理员可在管理工作台打开“穿搭图片复核”。页面展示封面和全部配图、文字、标签及原帖来源；图片全部加载成功、填写说明并勾选逐一检查确认后才能通过。图片加载失败时仍可填写原因并拒绝。遇到内容版本冲突，页面重新加载候选并清空旧确认，必须再次检查后提交。

`GET /api/v1/admin/trends/review-queue?limit=20` 返回最多50条待复核候选，包含图片、原帖、当前状态与 `fingerprint`。仅管理员可访问。

检查实际图片后，向 `POST /api/v1/admin/trends/{id}/content-review` 提交：

```json
{
  "approved": true,
  "fingerprint": "本次检查的当前内容版本，64位十六进制",
  "note": "已检查封面和所有拟发布图片，服装展示清晰，无身体特写或性暗示"
}
```

拒绝时 `approved` 为 `false`，说明具体原因。接口要求管理员会话、CSRF 和1到300字的复核说明，记录审计日志。内容版本变化返回409，必须重新检查后提交。文案明确违反内容范围的条目不能直接批准。普通用户、未登录请求和缺少 CSRF 的写入均无权批准。旧的批量 AI 审核接口没有恢复。

V13 迁移保留已有内容和复核历史，把未经本版本规则检查的记录转为待复核。`APPROVED`、隐藏状态和版本绑定由后端共同执行，前端标签或上传文件不能自行授予展示权限。待复核来源在页面标为“待复核”，避免与采集失败混淆。
