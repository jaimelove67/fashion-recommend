# 系统流程图更新说明

依据：当前《基于大模型的智能穿搭推荐系统_毕业设计成果.docx》第 1.2.7、2.3.4 节，以及现有用户与管理员用例图。

原图 2.1 只描述普通用户发起穿搭推荐后，前端、业务服务和外部服务之间的调用链。新增管理员后，该图仍可作为“智能穿搭推荐核心业务流程图”保留，但不能单独表示完整的系统总体流程。

本次使用 draw.io 原生可编辑节点重画两页，并通过本地 draw.io 导出 PNG、检查文字和连线：

- `智能穿搭推荐系统_系统流程图_管理员更新版.drawio`：含系统总体流程、管理员业务流程两个页面。
- `系统总体流程.png`：建议放在第 2.1 节，标题改为“智能穿搭推荐系统总体流程图”。
- `管理员业务流程.png`：建议放在第 2.3.4 节，图号按论文最终顺序编排。

总体流程增加独立的用户端和管理端入口、认证与角色校验、管理功能执行、操作记录及会话退出。管理员细图覆盖账号治理、授权趋势源维护、运行监控、审计与日志查询、图片清理任务及异常处理，并包含权限拒绝、只读或取消、配置校验失败、重试失败等分支。管理员不直接查看或修改普通用户私有衣橱，也不参与用户推荐生成。

核对过的反例：普通用户凭证不能进入管理分支；取消账号治理不会修改账号；趋势配置验证失败不会启用无效配置；清理任务重试失败不能被标记为处理成功；推荐参数或候选衣物不足不能继续正常生成。

实现边界：这两页表示论文更新后的目标设计。当前 README 仍声明不包含后台管理；AuthService 仅创建 USER 角色，SecurityConfig 尚未提供专门的管理端角色授权规则，当前前后端也未发现管理员业务模块。因此不能据此宣称管理员功能已实现。原有论文、用例图和业务代码均未覆盖修改。
