# 每周穿搭技巧自动整理

更新于 2026-10-16。目标约每周新增一条有依据、能用已有衣物实践的技巧；质量不足时跳过，不用旧文章改日期凑数。原有人工核读的五条技巧继续保留，自动内容排在前面。

## 来源与质量

1. 从配置的公开作者订阅源发现文章，也可配置具体的常青教程地址。默认来源为 Permanent Style 的 Style 和 Put This On 的 Guides 专题 RSS，优先穿法与教程而非综合新品流；这是公开来源发现，不依赖付费搜索接口，不读取登录后的私有文章。
2. 对候选逐篇读取实际文章页，提取正文。订阅摘要、付费墙、登录页、购物促销、空正文，以及声明 noAI / noarchive / nosnippet 的页面不能作为正文证据。来源独立失败，不影响其他可读来源。
3. 归纳必须引用至少两篇不同原文，提供至少三条来源要点、三至五个练习步骤、原因、假设对照、适用条件、取舍和自查。作者、来源和日期来自采集结果，不允许模型填写；未知信息保留未知。
4. 每条转述必须附带对应文章内的连续原文证据，后端做正文包含校验和直接复制检查。证据仅用于本次校验，不在公开接口返回原文片段或整篇正文。
5. 第二次独立请求对照相同正文，复核忠实度、可实践性、解释与取舍、新颖性；所有关键项通过、无问题且分数至少 85 才能发布。评分是模型审核结果，不是人工认证或效果保证。
6. ID、归一化标题、完整来源集合去重；已有五条人工整理的标题也会传给模型，避免重新包装旧技巧。不同主题可以复用部分来源。

采集最多六篇正文；进入模型最多四篇，每篇最多 24,000 字符，总正文最多 48,000 字符。超过预算时排除整篇，不静默截断限定语或反例。只提取文字，不声称读取或核验了原图与视频。自动内容在页面明确标注 AI 归纳、未经人工逐条核读；假设示例也与原帖事实分开。

## 更新频率与失败行为

- 默认每天上海时间 10:00 检查是否到期，启动 60 秒后补查一次。
- 数据库强制任意连续七天最多发布一条，任意连续七天最多两次尝试；失败后至少等待 48 小时。管理员手动触发遵守相同限制，没有强制绕过入口。
- 内容、成功时间、失败分类、尝试次数和租约持久化。重启不会重置配额，多实例通过事务锁与 15 分钟租约避免重复执行；旧任务不能覆盖后续任务。
- 来源不够、生成不合格或模型异常时保留已发布内容。公开读取接口不会触发采集或模型调用。
- 使用独立调度线程，避免慢请求阻塞每日趋势和图片清理。

## 模型与费用

复用管理后台“穿搭推荐”的文本模型、密钥和启停状态，不新增模型账号或付费搜索服务。自动整理仍会消耗现有模型服务商的 token 用量；每次尝试最多两次模型请求（初稿与复核），每七天最多四次请求。没有密钥、文本模型被关闭或单独关闭自动技巧时，不抓取文章、不调用模型，也不消耗尝试次数。

配置变量：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `OUTFIT_TECHNIQUES_ENABLED` | `true` | 自动整理总开关，仍受文本模型启停约束 |
| `OUTFIT_TECHNIQUES_REFRESH_CRON` | `0 0 10 * * *` | 检查时间，固定上海时区 |
| `OUTFIT_TECHNIQUES_INITIAL_DELAY` | `60000` | 启动补查延迟，毫秒 |
| `OUTFIT_TECHNIQUES_FEEDS` | 两个默认 RSS | 逗号分隔的公开 HTTPS 订阅源或文章列表页 |
| `OUTFIT_TECHNIQUES_ARTICLE_URLS` | 空 | 可选的具体原文地址，不能使用私有地址或凭据 |
| `OUTFIT_TECHNIQUES_MODEL_READ_TIMEOUT` | `60s` | 单次模型请求读取超时 |

来源 URL 只由部署配置决定，公开或管理员 API 均不接收任意 URL。每次连接及重定向都检查 HTTPS、配置域名与公网 DNS，限制响应大小、篇数和时间；不转发 Cookie 或用户凭据。DNS 预查不能替代部署出站网络限制，来源域名需要由维护者信任。

## 接口与持久化

| 方法与地址 | 权限与行为 |
| --- | --- |
| `GET /api/v1/outfit-techniques` | 公开只读，最近 24 条发布内容、最近发布日期、周更频率及状态 |
| `GET /api/v1/admin/outfit-techniques/status` | 管理员，尝试和成功时间、下次可尝试时间、错误分类与配额 |
| `POST /api/v1/admin/outfit-techniques/refresh` | 管理员与 CSRF，按同样配额尝试一次并记录审计 |

公开状态为 `ready`、`collecting`、`waiting-for-quality`、`disabled`。新表由 V14 迁移创建：`outfit_techniques`、`outfit_technique_attempts`、`outfit_technique_schedule`。文章全文只存在本次采集与模型请求的内存中，不进入这些表或日志；数据库仅保存原创归纳、来源元数据和有界审计字段。
