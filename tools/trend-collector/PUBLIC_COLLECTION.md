# 公开图文采集

内容规则见 [趋势内容范围与图片复核](../../docs/trend-content-policy.md)。正常半身穿搭和单品细节允许收录；身体特写和性暗示内容被排除。所有新采集记录进入后端待复核队列，经检查实际图片并确认后才公开，采集成功不等于已通过图片复核。更换图片会撤销原通过状态。

`collect_public.py` 用 Scrapling 普通 HTTP 请求读取微博公开详情页、小红书公开穿搭频道和 VOGUE 中国时髦学栏目。只请求 HTML，不请求或下载视频、图片文件，不登录、不处理验证页。

只接受有图片、有可核实发布时间、发表于最近七天且与穿搭有关的图文。小红书视频卡片在进入详情前排除；读取失败、日期不明、旧内容和带视频的文章只记录失败原因。互动数和全身照审核状态在无法取得时保留为未知。

在独立虚拟环境安装 `requirements-public.txt`，运行 `python collect_public.py`。默认结果写入 `data/public-image-posts/feed.json`，采集状态写入同目录的 `report.json`。脚本只生成候选数据，不覆盖原有平台导入文件。微博默认种子链接是本次验证的有限样本，不能视为全平台搜索或完整覆盖；需要采集其他博主时应换成其可公开访问的原帖链接。

旧候选脚本与每日自动采集服务分开运行。后端默认连接每日采集服务，支持微博、抖音和小红书；取消端点配置后才读取对应的本地导入文件。候选脚本中的出版物内容不作为日常穿搭帖子导入。3D画廊优先使用经过确认的全身照，也允许通过内容与图片复核的图片帖配图；本工具不会自动添加全身照确认。

验证：`python -m unittest discover -s tools/trend-collector -p test_collect_public.py -v`（从项目根目录运行）。

内容排除规则检查标题、作者和完整正文，再生成短摘要；排除时装周、秀场、红毯与含明星、艺人、演员、歌手、演唱会等明确线索的内容。完整正文只用于筛选，不输出到 feed。普通合格图文通过趋势页内容卡片展示，不依赖全身照核验字段。

## 每日自动搜索

`daily_collector.py` 使用项目固定版本的 Scrapling `DynamicFetcher`，在微博、抖音和小红书分别搜索“男士穿搭”“女士穿搭”“小众风格穿搭”，微博按时间排序，抖音只读取搜索页面实际加载的公开搜索响应。使用独立无头浏览器，不要求用户开启远程调试，不读取用户浏览器配置、Cookie 或私密响应。只接受最近24小时、可核实发布时间、有图片且符合穿搭规则的帖子；不自动宣称全身照已审核。

每日展示目标是跨平台合计5套：2套男装、2套女装、1套小众风格欣赏。采集器为这个目标准备候选，不会按每个平台各选5套。三条查询的结果交错合并、按稳定帖子ID去重，每平台最多保留50条候选，交由后端在已复核内容中统一选取。搜索词不会充当帖子分类依据；分类读取原帖标题、摘要、完整正文和原有标签，不根据作者姓名、外貌或粉丝数猜测。

候选数据沿用 `topicTags`：明确的男装、男士/男生穿搭文案添加“男装穿搭”，女装同理；“不是男装穿搭”等否定描述不产生该标签。同时正向提及两种服装对象，或明确为男女同款、男女通穿、无性别穿搭、unisex 时，保留“男女装”歧义标记，不强行二选一。这个标记来自完整原文，即使相关说明在短摘要中被截断，后端仍可识别并排除单一男女配额。哥特风、洛丽塔、蒸汽朋克、赛博朋克、视觉系和暗黑先锋等具体风格词添加“小众穿搭”与对应风格名，明确“不是哥特风”等否定用语不作为依据。“小众品牌”“粉丝少”或单独的“小众”营销词不会得到小众风格标签，小众风格与小众博主粉丝分层是两件事。标签属于可复核的文字初筛，仍需通过原有图片与内容复核；不能据此宣称已识别实际穿着者性别、已看懂图片或已证实风格。全文不随候选输出，保留原帖链接供复核。

三条查询都成功才原子替换该平台候选文件；其中一条失败时保留旧的完整文件并返回503，不把部分男装/女装结果记为当天完整搜索。状态文件包含实际关键词、已完成查询数、24小时范围、候选数和目标配额。成功不表示已凑齐2+2+1；没有足够的合格来源或尚未复核时，应如实保留缺额，不能复制、改时间或放宽图片复核来补齐。显式传入 `keyword` 时仍只搜索该词，供现有按需登录验证入口使用。

服装对象词只接受“男士/女生穿搭”“男士衬衫穿搭”“女生日常通勤穿搭”等明确表达，不跨任意文本寻找“穿搭”。“男生帮我拍的穿搭”“女生拍摄的穿搭”“男生眼中的穿搭”仅描述拍摄者或观察者，不因此标为男装或女装；同句另有明确服装对象时以该对象为依据。

Compose 的 `trend-collector` 服务只在内部网络提供 `/weibo.json`、`/douyin.json`、`/xiaohongshu.json`。后端启动后抓取一次，之后北京时间每天12点调用这些来源。服务按平台原子写入 `data/<platform>.json` 和 `data/<platform>-collection-status.json`。成功但无合格帖子返回空列表；登录墙、验证页、结构无法解析或网络失败返回503并保留上次文件，不修改旧条目的时间。后端预置样本回退在本地环境关闭。

启动：`docker compose --profile app up -d --build trend-collector backend frontend`。本地实测：`tools/trend-collector/.venv/Scripts/python.exe tools/trend-collector/daily_collector.py --real-chrome --output output/scrapling-trends`。Windows的`--real-chrome`由Scrapling启动已安装Chrome的独立实例；Docker默认使用安装的Chromium。

目前匿名公开搜索可能被平台跳转到登录/验证页，Scrapling不能保证每天都有可用结果。采集状态记录实际失败原因。必须先验证平台可用性，不能将服务启动或HTTP200视为采集成功。

采集范围：平台不设硬性名单，优先微博、抖音和小红书的日常穿搭图文。`daily_collector.py` 同时搜索小红书图文，每条查询最多读取3条正常图文详情验证发布时间，默认三条查询合计最多9条。视频、纯文字、时装周、秀场、红毯、明星、杂志大片均不导入；后端展示层也检查媒体类型，以排除已存旧视频。其他平台可通过通用来源接口接入；所有平台均需通过内容与图片复核后才能公开，画廊对平台不设硬性名单。

## 用户授权的微博登录验证

`logged_in_weibo.py` 连接用户明确授权的独立 Chrome 采集窗口。窗口使用项目中已忽略的独立配置目录，并仅在本机开放调试端口；用户在窗口内完成登录和验证码。脚本只操作自己创建的公开搜索页和原帖页，不读取或导出 Cookie、密码、浏览器存储或私密内容。完成后只关闭自己创建的页签，并断开连接，保留用户浏览器。

从项目根目录运行：

```powershell
& tools/trend-collector/.venv/Scripts/python.exe tools/trend-collector/logged_in_weibo.py --output output/weibo-review
```

默认浏览器地址是 `http://127.0.0.1:9222`，可用 `--browser-url` 指定其他本机端口。搜索词默认为“穿搭”。无需新增依赖，沿用 `requirements-public.txt` 的环境。Chrome 必须保持打开且登录仍有效；连接失败或出现登录墙时记录失败并保留上次文件。这个入口用于按需采集，Docker 每日匿名服务不会自动使用该登录窗口。

搜索页仅显示“几分钟前”等相对时间时，脚本最多进入10条候选原帖，读取与原帖链接对应的绝对时间；无法核实的日期保留未知并排除，不用采集时间推算发布时间。支持页面实际展示的“今天01:32”和“26-10-15 09:40”格式。优先读取展开全文，避免重复拼接预览和全文。原帖数字编号作为稳定 ID，保持登录与匿名采集间去重一致。

输出仍为 `weibo.json` 与 `weibo-collection-status.json`，使用同一最近24小时图文约束；图片和视频文件不下载，互动数与全身照审核保持未知。默认写入 `data/logged-in-weibo` 候选目录。关键词排除属于初筛，可能漏掉只写人名的明星内容、粉丝动态或无关讨论，接入页面前仍需复核。复核后的文件可通过后端已有的本地导入方式读取；该平台配置了采集端点时，端点优先于导入文件。

验证：`tools/trend-collector/.venv/Scripts/python.exe -m unittest discover -s tools/trend-collector -p 'test*.py' -v`。新增检查覆盖原帖日期对应关系、视频跳过、登录失败、连接范围、稳定 ID 以及不关闭用户会话。
